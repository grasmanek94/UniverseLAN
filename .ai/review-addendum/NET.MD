## Fresh notes recorded before baseline comparison

1. **Framing and evolution.** Both routing and body decoding construct a cereal portable archive, so the endian byte is consumed before the 64-bit discriminator; GalaxyID uses numeric `uint64_t` minimal serialization. Eight-byte frames fail while reading the discriminator rather than permitting an out-of-bounds raw read. However, class-name IDs carry no schema version. Five lobby-update layouts insert `fail_reason` after 1.124.0; `LeaveLobbyMessage` changes bool to enum at 1.133.0; ChatMessage inserts type at 1.110.0. The handshake has no version negotiation. Matching-version server binaries are generated, which limits the cross-version deployment claim. Exact frame consumption and semantic validation are absent.
2. **Decode/admission boundary.** Server handlers check authentication only after Shared materializes arbitrary message containers. Vendored cereal string/vector loaders resize from the wire length before checking available bytes. Transport packet limits therefore do not bound transient decoded allocation. Shared catches decode exceptions, but `make_shared<T>()` and handler execution sit outside that catch. Null nested P2P packets are actually rejected by both Server and Client's AddPacket; do not infer a null dereference from the schema alone.
3. **Authentication state.** Challenge comparison sets `completed` before ID insertion/linking; failure calls the vendor's immediate disconnect. Crucial counterevidence: that function resets incoming queues synchronously and generates no local disconnect event. A simplistic queued-follow-up-packet admission bypass is therefore unproven. Cleanup/accounting after this path and broadcasts to transport-connected, unadmitted peers require specific review. Shared-key LAN membership itself is intentional, not evidence of a security defect.
4. **Ownership and reconnect.** RECEIVE packets have a dispatch scope guard; failed client sends are destroyed. Server Send allocates then returns the vendor status without destroying failed packets; vendor explicitly retains caller ownership on failure. Both broadcast implementations destroy packets if nobody accepts them. Client queues are drained on disconnect, but pending application requests are not completed by this drain. Disconnect is also queued before cleanup and synthesized after it, so duplicate notification depends on a concurrent consumer; it is not unconditional. Reconnect resets a peer slot in an existing host, not freed host storage.
5. **Domain invariants.** Chat history selection handles missing references, zero limit, and bounds using iterator positions. Unread count saturates rather than underflows. Server creates complete two-member rooms before publishing and reconstructs chat/lobby sender identity. Client history notifications deduplicate IDs, while ChatRoom's direct append primitive does not. Lobby mutation permission belongs to actual Server callers; ChooseNewOwner's caller explicitly invokes SetOwner. Lobby/member deletion stores an empty value; SDK documentation explicitly equates Delete with Set(empty), so count/enumeration semantics need care before alleging a defect. Member/lobby counts and enum/ID relationships are not validated on archive load.
6. **Windows persistence.** INI loading uses wide filesystem paths and SimpleIni Unicode mode, but configured narrow data-path values are later passed to `filesystem::path`. Dirty achievements are cleared before unchecked SaveFile; independent load/modify/save operations have no transaction. SharedFileUtils Open is lookup-only, even for output modes. Server uses it for an initially nonexistent share-counter file. Timestamp forwarding inherits the file clock epoch, not automatically Unix time. Shared copies share container ownership; the dependency's entries retain a raw parent pointer, so retained entry handles require a demonstrated owner-lifetime path before a UAF claim.
7. **Routing and external evidence.** Read Server/Client dispatch, full ServerHandlers, Peer and Challenge, full Chat/Matchmaking handlers, networking AddPacket, storage transfer callbacks and workers, User data/state handlers, ENet++ and relevant ENet/cereal contracts. `enet_host_service` clears event fields before ordinary error returns, countering an automatic stale-packet/double-free conclusion. Source-derived concerns remain subject to baseline comparison and SDK contract checks below.

## Independent counterevidence and coverage challenges

- **Decode ownership correction:** The receive packet is reliably destroyed on ordinary unwind, but cereal's untyped shared-pointer registry can construct a room self-cycle via a supposed ChatMessage reference. That concrete rejected-graph mechanism is now included under BASE-NET-001. Null-pointer validation alone, an outer catch, or an aggregate byte cap alone is insufficient.
- **Authentication admission state:** Challenge::Validate sets `completed` before ID uniqueness/link success; rejection uses immediate vendor disconnect without normal Server cleanup. However, vendor `peer.c:506-537` explicitly suppresses a local disconnect event and clears pending transport queues synchronously. Do not promote "a second already queued request immediately dereferences uninitialized user_data" without showing a transport path after that reset. The real cleanup/slot-reuse issue remains a SERVER handoff; outbound broadcast admission has its own demonstrated path in ADD-NET-001.
- **Field validation must follow consumers:** Null P2PServer packet is rejected by Server and by Client NetworkingImpl::AddPacket; null lobby-list entries are skipped, and null CreateLobby response represents failure. Those schema shapes alone are not crashes. Chat history vector elements are dereferenced without null checks, but normal Server constructs them non-null; a hostile/malformed configured server is the direct boundary for that client defect. User/SetLobbyMemberData/lobby/chat sender fields are replaced by peer identity on their normal server routes. Invalid rich-presence action can preserve a supplied success flag, but no arbitrary state-write impact was established; retain SERVER validation handoff.
- **Transport and generation:** Failed server sends leak; broadcasts do not share that ownership failure. ENet ordinary service errors reset event fields, so truthy negative Pull is error swallowing rather than automatic stale receive double-free. A popped old callback may enqueue stale work after Cleanup, but no native peer UAF is proved by that fact. ADD-NET-003 establishes the independently observable loss of terminal operation completion. A generation-aware repair should address both without conflating them.
- **Chat caller contract correction:** Baseline context notes say the borrowed incoming vector remains dangling after successful Chat callback return. The pointer is indeed not cleared, but SDK 1.152.11 `IChat.h:253-266` restricts GetChatRoomMessageByIndex to the notification callback and a valid index. Calling it after return or out of range is not a conforming production-crash demonstration. Reentrant nested ProcessData/callback restoration is a separate unresolved schedule; no NET UAF ID was added. ADD-NET-004 uses conforming requests/listeners and requires no stale-pointer call.
- **Chat/lobby data invariants:** Exclusive-reference history slicing and saturating unread subtraction are sound for normal non-null vectors. Server publishes completed room membership, checks history/chat membership and reconstructs sender/time/IDs. ChooseNewOwner's caller invokes SetOwner explicitly. SDK DeleteUserData/DeleteLobbyData/DeleteLobbyMemberData explicitly equal Set(empty); no erase/count defect is counted without a stronger contract. Owner/capacity/type validity remains caller policy: actual direct Join ignores joinability and update helper ignores its rollback callback, both preexisting SERVER/API handoffs.
- **Persistence/Windows boundaries:** No doubled-absolute-path defect: an absolute base replaces the earlier filesystem operand. Wide boot-file opening and UTF-8 configured-path conversion are distinct. Counter Open is lookup-only; share-ID restart/copy collisions remain SERVER/UTIL handoffs. Raw file-clock timestamps reach SDK APIs without Unix conversion; keep UTIL/STORAGE ownership. Entry handles have raw container parents, but inspected Storage teardown joins upload workers while their owner is alive; a generic retained-entry UAF was not promoted without a live escape path.
- **Protocol evolution and endian:** Numeric archive framing includes its endian marker on both routing passes; the eight-byte preliminary check causes a caught short read, not an unchecked read of byte 9. Windows x86/x64 fixed-width fields agree. Schema gates, pointer graphs and semantic enum/ID relationships remain separate concerns. Server direction-only no-op handlers still decode their unused payloads; separating request/response DTOs reduces this unnecessary pre-admission graph surface.
